## .claude.md

### Project Overview

This project develops custom **Devcontainer Features** following the [Devcontainer Features Specification](https://containers.dev/implementors/features/). The architecture utilizes a **"Bootstrap to Ansible Role"** pattern to ensure idempotent installation on **Red Hat UBI9/UBI10**.

### Core Architecture Stack

* **Base Image:** Red Hat Universal Base Image 9 (UBI9).
* **Bootstrap Tooling:** `uv` is installed to `/usr/local/bin/` in the Containerfile. Feature `install.sh` scripts use `uv run --with ansible-core ansible-playbook` to execute Ansible playbooks as root.
* **Installation Logic:** `install.sh` triggers `ansible-playbook` which executes the local `ansible-role-feature`.
* **Target Paths:** Prefer `~/.local/bin/` for binaries and `~/.local/share/<tool>/` for tool data to ensure userland isolation.
* **Inventory:** Each feature includes its own `hosts.yml` file (self-contained).

### Feature Directory Structure

Every feature must strictly follow this skeleton:

```text
<feature-name>-feature/
├── devcontainer-feature.json    # Feature metadata, options, containerEnv, extensions
├── install.sh                   # Entry point (runs as root, executes Ansible via uv)
├── activate-feature.yml         # Playbook that calls the local role
├── hosts.yml                    # Ansible inventory (UBI9/UBI10 localhost)
├── ansible-role-feature/        # Standard Ansible Role structure
│   ├── defaults/main.yml        # Default versions, URLs, checksums
│   ├── tasks/main.yml           # Implementation logic (download, extract, verify)
│   ├── vars/main.yml            # Compatibility list (ubi9, ubi10)
│   └── meta/main.yml            # Role metadata (author, platforms, tags)
├── NOTES.md                     # Developer notes
└── README.md                    # Documentation (optional)
```

### Implementation Standards

#### 1. The `install.sh` Bootstrap

The script runs as root per the devcontainer spec. It:

1. Prints a banner and devcontainer user environment variables
2. Verifies `uv` is available
3. Validates the Ansible inventory with `ansible-inventory`
4. Runs the playbook: `uv run --with ansible-core ansible-playbook --inventory ./hosts.yml activate-feature.yml -e "remote_user=${_REMOTE_USER}" -e "remote_user_home=${_REMOTE_USER_HOME}" [extra vars]`

#### 2. UBI9/UBI10 Compatibility

* Use `ansible.builtin.package` (dnf) for system dependencies (e.g., `libicu`, `openssl-libs`, `unzip`).
* Configure UBI BaseOS repository when system packages are needed.
* Prefer downloading static binaries or archives over adding external repositories.
* Compatibility list in `vars/main.yml`: `[ubi9, ubi10]`.

#### 3. Installation Patterns

* **Direct binary download** (jq, yq, pnpm): `get_url` directly to `~/.local/bin/<tool>` with mode `0755`.
* **Tarball with flat structure** (grype, syft, .NET): `unarchive` to target directory.
* **Tarball with nested directory** (Go, Node.js, OpenJDK, UV): Use `tar --strip-components=1` via `ansible.builtin.command`.
* **Zip archive** (Bun): `unarchive` to temp dir, then copy binary to `~/.local/bin/`.
* **Checksums file**: Download and parse checksums file when available; support direct checksum via option.
* **UV tool install** (Ruff, ansible-core): Use `uv tool install <pkg>==<version>` as target user via `become_user`.
* **UV python install** (Python): Use `uv python install <version>` as target user.

#### 4. Environment Variables

The `devcontainer-feature.json` must use `containerEnv` to configure PATH and tool-specific vars:

```json
"containerEnv": {
    "PATH": "${containerUserHome}/.local/share/<tool>/bin:${containerUserHome}/.local/bin:${localEnv:PATH}"
}
```

#### 5. Variable Naming

* `install.sh` passes `remote_user` and `remote_user_home` (from `_REMOTE_USER` / `_REMOTE_USER_HOME`).
* `activate-feature.yml` maps to role vars with `_` prefix: `_target_username`, `_target_user_home`.
* Role defaults use `_<tool>_version`, `_<tool>_tarball`, `_<tool>_download_url` pattern.

### Security & Compliance

* **Integrity:** Always validate checksums in Ansible `get_url` tasks when available.
* **No bootstrap user:** Features run directly as root (no `su` to bootstrap user).
* **Ownership:** Set correct file ownership (`_target_username:_target_username`) after extraction.
