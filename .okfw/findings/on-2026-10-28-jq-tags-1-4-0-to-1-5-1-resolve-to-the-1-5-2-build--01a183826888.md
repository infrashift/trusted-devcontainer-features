# On 2026-10-28, jq tags 1.4.0 to 1.5.1 resolve to the 1.5.2 build

On 2026-10-28, four version tags of `ghcr.io/infrashift/trusted-devcontainer-features/jq` had the same manifest digest: `1.4.0`, `1.5.0`, `1.5.1` and `1.5.2`.

## Source of the measurement

* Command, for each tag: `skopeo inspect --raw docker://ghcr.io/infrashift/trusted-devcontainer-features/jq:<tag> | sha256sum`.
* Run on 2026-10-28.

## Result

| Tag | Digest (first 16 hex) |
|---|---|
| `1.0.0` | `c1285886c4d6622e` |
| `1.0.1` | `bc6253e8b7160c1b` |
| `1.2.0` | `63a6c3a81e9f6211` |
| `1.2.1` | `5f1fe75b3cfcfda5` |
| `1.3.0` | `05c83660958c7117` |
| `1.4.0` | `3c69ad14e10268f5` |
| `1.5.0` | `3c69ad14e10268f5` |
| `1.5.1` | `3c69ad14e10268f5` |
| `1.5.2` | `3c69ad14e10268f5` |
| `1.5.3` | `d5dabb81c9046908` |
| `latest` | `d5dabb81c9046908` |

## Analysis — not part of the measurement

Each version has a different `version` field in its metadata, so two versions cannot have the same bytes. Thus `1.4.0`, `1.5.0` and `1.5.1` point at the 1.5.2 build. This agrees with the defect that PR #23 fixed on 2026-10-09. The tags from 1.5.3 are correct. Other features were not measured.
