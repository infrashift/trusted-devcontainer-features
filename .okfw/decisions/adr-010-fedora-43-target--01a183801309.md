# ADR-010: Fedora 43 target

ADR-010 makes the features work on Fedora 43 and on UBI. The `bootstrap` feature reads the OS variant once from `/etc/os-release` and writes it into the generated inventory. Each role then asserts that the variant is in its list of tested variants.

**Status:** Accepted. Supersedes [ADR-001: UBI 9 base image](/decisions/adr-001-ubi-9-base-image--01a183801183.md).

## Decision

Map `ID=rhel` to `ubi<major>`, `ID=fedora` to `fedora<major>`, and other IDs to `<id><major>`. Delete the per-feature `hosts.yml` files, which always set the variant to `ubi9`, so the old assert always passed. Use `setpriv` to drop privileges, because `su` and `runuser` need PAM, which fails in a container build.

## Code check on 2026-10-28

The code agrees. `src/bootstrap/install.sh` has the `case` statement. No `hosts.yml` exists in `src/`. Each role lists `ubi9`, `ubi10` and `fedora43` in `_securedevcontainer_compatibility_list`. The ADR mentions a `sudo` feature, but no `sudo` feature exists in `src/` now.

## Features affected

All features. See [Feature: bootstrap](/features/feature-bootstrap--01a183800d4f.md).
